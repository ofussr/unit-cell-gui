# Проверка unit-cell-gui 0.2.5

Выпуск относительно 0.2.4 включает проверенный пользователем depth peeling
из локальной .01 и новое внешнее управление непрозрачностью полиэдров.
Код, wheel, sdist и метаданные имеют версию `0.2.5`. Публикация не выполнялась.

## Новый API и работа GPU

`set_polyhedron_opacities({index: value})` принимает реальные конечные числа
от 0 до 1; `None` снимает конкретное переопределение. Индексы относятся к
исходному Scene.polyhedra. Значение 0 скрывает объект, 1 делает его непрозрачным.
Новый необязательный аргумент `update_scene(polyhedron_opacities=...)`
позволяет объединить изменение материала и геометрии в атомарный пакет.
`get_polyhedron_opacities()` возвращает независимую копию эффективных значений.

Материалы хранятся в R32F texture buffer — один float на исходный полиэдр.
Прозрачные/непрозрачные группы выбирают уже загруженные диапазоны геометрии.
Тест одного изменения при активном прозрачном проходе подтверждает загрузку
4 байт, а двух соседних значений — 8 байт одним вызовом. Создание mesh,
полный geometry cache и glBufferData при этих изменениях не вызываются.
Для граничных значений не требуются пересборка или замена геометрии;
могут создаваться/освобождаться служебные FBO или обновляться прежние индексы
порядка рёбер при переходе между путями отрисовки.

GPU-записи вершин держат базовые материалы внешней программы. Отдельная
таблица применяется только при наличии локальных opacity-переопределений,
чтобы прежние вызовы не добавляли новое чтение материала в vertex shader.
Меняются заливка, физические рёбра и явно переопределённые контактные линии.
Значение 0 также убирает штриховку. Положительные значения в чёрно-белом
режиме сохраняют непрозрачную гравюру, а дробные значения остаются для
возврата в цветной режим. Глобальная/site-видимость по-прежнему ограничивает
отрисовку. Сброс очищает локальные значения; set_scene начинает новое состояние.

## Проверки

- 88 тестов прошли без пропусков для исходников и установленного wheel.
- Ещё 12 проверок opacity/depth peeling прошли при QT_SCALE_FACTOR=2.
- Реальный OpenGL 3.3 Core / GLSL 330, Linux/Xvfb, Mesa/llvmpipe,
  Python 3.12, NumPy 2.5.3, PySide6 6.11.2, PyOpenGL 3.1.10.
- Ошибочные opacity-пакеты не меняют ни один включённый объект. Проверены
  индексы, NaN/inf/границы диапазона, типы, пустая сцена, защитная копия,
  слияние, None, повторный no-op, стили, режимы и сброс.
- Цвет при 0, дробных значениях и 1 сравнивается с независимо вычисленным
  alpha-over, допуск 1 из 255. Проверены переходы для исходно прозрачных
  и исходно непрозрачных GPU-буферов без генерации геометрии.
- Пакеты с атомами, заменённым полиэдром и opacity совпадают пиксельно с
  полной подготовкой соответствующего состояния. Нулевой объект исключён
  из штриховки. Контекст восстанавливает материалы и освобождает их ресурсы.
- Действуют прежние проверки instancing, геометрии, заселённости, цвета
  контактов, частичных обновлений, предельного размера texture-buffer и cleanup.
- Для depth peeling проверены разные порядки в разных пикселях пересекающихся
  граней, независимость от порядка входных объектов, приглушение заднего
  ребра, блокировка непрозрачной поверхностью и обработка 40 слоёв.
- Пример внешнего приложения проверен с установленным wheel: opacity-slider
  0/35/100, перенос атома, изменение полиэдра и сброс.
- Прежние 25 публичных методов сохраняют старые вызовы. Только update_scene
  получил новый необязательный keyword; добавлены два метода opacity.
  Модели и зависимости не изменены.
- Все 11 Python-файлов исходников и установленной копии совпадают с wheel.
  Wheel, пересобранный из sdist, имеет побайтово идентичное содержимое записей.
  Sdist содержит новые тесты, пример, API-контракт и релизноутс; локальные
  экспериментальные заметки в него не включены.
- Python-код скомпилирован в байткод; GLSL компилировался и линковался при
  фактическом рендеринге. Wheel/sdist прошли twine check --strict;
  git diff --check прошёл.

## Изображения

46 контрольных сцен при обычном масштабе и те же 46 при двойном. Без новых
opacity-вызовов все 92 кадра совпали с проверенной локальной 0.2.4.01
пиксель в пиксель, включая цвет/гравюру, пересечения, фильтры, заселение,
поворот, масштаб, перенос, resize, прозрачные/непрозрачные полиэдры и связи.

Относительно официальной 0.2.4 сохраняются намеренные изменения depth peeling:
правильный порядок граней и рёбер и профиль сглаживания прозрачного пути.
Для старой/новой прозрачности приложен синтетический пример demo.png.
Исходная пользовательская структура не была передана, поэтому пример
не является воспроизведением её скриншота. Сравнения покрывают эти сцены,
а не все возможные входные данные.

## Измерения

Окно 640 × 480, по 2 прогревочных и 8 измеренных кадров, вращение плюс чтение
framebuffer. Два последовательных запуска на программном рендерере сравнивают
локальную 0.2.4.01 и финальную 0.2.5 без opacity-переопределений.

| Сцена | 0.2.4.01, мс | 0.2.5, мс | Слоёв в 0.2.5 |
|---|---:|---:|---:|
| 580 атомов без полиэдров | 117.30 | 87.40 | 0–0 |
| 2 полиэдра с атомами | 25.60 | 21.67 | 8–10 |
| 12 сильно перекрывающихся полиэдров | 174.65 | 150.10 | 24–27 |
| 2 пересекающихся куба | 30.94 | 33.11 | 7–7 |

Во всех измеренных кадрах загружено 0 байт геометрии. Эти числа включают
software rendering и readback, зависят от нагрузки и не предсказывают FPS
на аппаратном GPU. Послойная отрисовка остаётся существенно дороже старого
ошибочного порядка при большом числе перекрытий. Прозрачный путь требует
семь служебных текстур, около 49 MB при 640 × 480 физических пикселях;
удвоенный DPR увеличивает эту память четырёхкратно. Материал дополнительно
занимает 4 байта на полиэдр, без накладных расходов драйвера.

Windows и аппаратные драйверы здесь не проверялись. Пользователь подтвердил
исправление перекрытий и отсутствие заметного падения скорости на своей
структуре для предшествующего локального depth-peeling выпуска.
